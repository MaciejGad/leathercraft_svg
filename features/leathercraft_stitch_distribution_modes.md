# Stitch Distribution Modes — Development Specification

This document describes how stitch and hole distribution modes should work in `leathercraft_svg` and the `.lcraft` DSL.

The main goal is to improve how stitch holes and laser stitch marks are placed along shape edges or paths.

Currently, stitching is based mostly on a fixed spacing value. This is simple, but it can produce uneven-looking results when the edge length is not divisible by the spacing. For leathercraft patterns, it is often better to keep the first and last stitch in controlled positions and distribute the remaining stitches evenly between them.

This document focuses especially on a new distribution mode:

```text
fit_evenly
```

---

## 1. Goals

Add support for different stitch and hole distribution strategies.

The library should support at least:

```text
fixed_spacing
fit_evenly
fixed_count
```

Recommended first implementation:

```text
fixed_spacing
fit_evenly
```

The feature should work for both:

- round holes generated by `add_holes`
- laser stitch segments generated by `add_stitch_pattern`
- open polyline stitches generated by `add_stitch_on_polyline`
- DSL `holes`
- DSL `stitches`

---

## 2. Problem

With fixed spacing, a 103 mm edge and 5 mm spacing cannot divide evenly.

Depending on current implementation details, this may produce:

```text
5, 10, 15, ..., 100
```

or similar placement.

That leaves a 3 mm remainder near one side. In leathercraft this can look visually unbalanced, especially on visible seams.

A more professional result would be to calculate the number of stitches that approximately matches the requested spacing, then adjust the actual spacing so the row fits neatly.

Example:

```text
usable length = 103 mm
requested spacing = 5 mm
number of intervals = round(103 / 5) = 21
actual spacing = 103 / 21 = 4.904761...
```

This gives visually balanced placement from start to end.

---

## 3. Distribution modes

### 3.1 `fixed_spacing`

This is the current behavior and should remain the default for backward compatibility.

Meaning:

```text
Place stitches every N millimeters.
Do not adjust spacing to fit the edge.
```

Example:

```python
doc.add_holes(
    shape,
    spacing=5.0,
    distribution="fixed_spacing",
)
```

DSL:

```text
holes
  source panel
  spacing 5
  distribution fixed_spacing
end
```

If no distribution is specified, this mode should be used.

---

### 3.2 `fit_evenly`

This mode adjusts the real spacing so stitches or holes are evenly distributed across the selected edge, contour, or path.

Meaning:

```text
Use the requested spacing as a target.
Calculate a count from the available length.
Adjust actual spacing so the row fits evenly.
```

Example:

```python
doc.add_holes(
    shape,
    spacing=5.0,
    distribution="fit_evenly",
)
```

DSL:

```text
holes
  source panel
  spacing 5
  distribution fit_evenly
end
```

This mode should be especially useful for:

- wallet panels
- card pockets
- watch straps
- lighter sleeves
- key fobs
- visible decorative stitch rows
- symmetrical patterns

---

### 3.3 `fixed_count`

This mode uses an explicit number of stitches or holes instead of spacing.

Meaning:

```text
Place exactly N stitches or holes along the available length.
Calculate spacing automatically.
```

Example:

```python
doc.add_holes(
    shape,
    count=12,
    distribution="fixed_count",
)
```

DSL:

```text
holes
  source panel
  count 12
  distribution fixed_count
end
```

Recommended for a later implementation. The first version can postpone this mode if needed.

## 4. Recommended Python API changes

### 4.1 `add_holes`

Current signature:

```python
doc.add_holes(
    shape,
    edges="all",
    spacing=5.0,
    hole_radius=1.2,
    inset=4.0,
    layer="cut",
    include_corners=False,
    rounded_path=False,
)
```

Recommended new signature:

```python
doc.add_holes(
    shape,
    edges="all",
    spacing=5.0,
    hole_radius=1.2,
    inset=4.0,
    layer="cut",
    include_corners=False,
    rounded_path=False,
    distribution="fixed_spacing",
    count=None,
)
```

Rules:

- `distribution="fixed_spacing"` preserves current behavior.
- `distribution="fit_evenly"` uses `spacing` as target spacing.
- `distribution="fixed_count"` uses `count`.
- `count` is ignored unless `distribution="fixed_count"`.
- Invalid distribution values should raise `ValueError` or the library's equivalent validation error.

## 5. Recommended internal model

The implementation should centralize stitch placement logic in one or more reusable helper functions.

Suggested helper:

```python
def distribute_distances(
    length: float,
    spacing: float,
    *,
    distribution: str = "fixed_spacing",
    count: int | None = None,
    include_start: bool = False,
    include_end: bool = False,
    min_count: int = 1,
) -> list[float]:
    ...
```

It should return distances measured from the beginning of the path or edge.

Examples:

```python
distribute_distances(100, spacing=10, distribution="fixed_spacing")
# [10, 20, 30, ..., 90]

distribute_distances(100, spacing=10, distribution="fixed_spacing", include_start=True, include_end=True)
# [0, 10, 20, ..., 100]

distribute_distances(103, spacing=5, distribution="fit_evenly", include_start=True, include_end=True)
# [0, 4.9047, 9.8095, ..., 103]

distribute_distances(100, spacing=5, distribution="fixed_count", count=6, include_start=True, include_end=True)
# [0, 20, 40, 60, 80, 100]
```

## 6. How `fit_evenly` should calculate spacing

### 6.1 Basic formula

Given:

```text
length = available path length
target_spacing = requested spacing
```

Calculate:

```text
interval_count = round(length / target_spacing)
actual_spacing = length / interval_count
```

Then place points every `actual_spacing`.

### 6.2 Minimum interval count

`interval_count` should never be less than 1.

```python
interval_count = max(1, round(length / target_spacing))
```

### 6.3 Count with endpoints included

If both endpoints are included:

```text
point_count = interval_count + 1
```

Example:

```text
length = 100
target_spacing = 30
interval_count = round(100 / 30) = 3
actual_spacing = 33.333
points = 0, 33.333, 66.667, 100
```

### 6.4 Count without endpoints

If endpoints are not included, there are two reasonable approaches.

Recommended simple approach:

1. Calculate interval count as above.
2. Use actual spacing.
3. Place points at `actual_spacing`, `2 * actual_spacing`, etc.
4. Skip 0 and skip `length`.

Example:

```text
length = 100
target_spacing = 30
interval_count = 3
actual_spacing = 33.333
points = 33.333, 66.667
```

This produces fewer points but avoids placing directly on endpoints.

Alternative center-balanced approach:

```text
point_count = max(1, round(length / target_spacing))
actual_spacing = length / point_count
first = actual_spacing / 2
points = first, first + actual_spacing, ...
```

Recommended first implementation: use the simple approach because it aligns naturally with `include_corners`.

Future option:

```text
alignment center
```

could enable the center-balanced approach.

## 7. Interaction with `include_corners`

The existing `include_corners` parameter controls whether stitches or holes extend to corners.

The new distribution mode should not replace `include_corners`.

Recommended behavior:

```text
include_corners=False
```

Do not place stitches or holes at the exact start/end/corner positions.

```text
include_corners=True
```

Allow stitches or holes at exact start/end/corner positions.

For `fit_evenly`, this means:

```python
include_start = include_corners
include_end = include_corners
```

For closed contours, the implementation should avoid duplicate start/end points if they represent the same physical point.

---

## 8. Interaction with selected edges

For shapes with edge indices, distribution should be calculated per selected edge, not across the whole selected set, unless the user explicitly requests continuous mode later.

Example:

```python
doc.add_holes(
    rectangle,
    edges=[0, 2],
    spacing=5,
    distribution="fit_evenly",
)
```

Expected:

```text
Top edge is fitted independently.
Bottom edge is fitted independently.
```

This gives predictable results.

Future option:

```python
continuous=True
```

could distribute across the combined path length, but this is not recommended for the first implementation.

---

## 9. Interaction with rounded and closed contours

For shapes that already treat the full contour as a path, `fit_evenly` should apply to the whole contour.

Examples:

- `Circle`
- `Ellipse`
- `Stadium` with `edges="all"`
- `RoundedRectangle` with `edges="all"` if the current implementation follows the rounded contour
- `RoundedTriangle` with `rounded_path=True`
- `Polygon`

For closed contours, avoid duplicating the first and last point because they are the same physical position.

Recommended behavior for closed paths:

```text
include_corners=False
```

Distribute points around the contour with no duplicate at the seam.

```text
include_corners=True
```

For closed contours this should usually behave the same as `False`, unless the shape has meaningful vertices/corners and the implementation explicitly supports them.

Reason: on a circle, there is no meaningful corner. On a closed polygon, adding both start and end creates duplicate holes.

---

## 10. Interaction with stitch length

For laser stitch lines, `stitch_length` should remain independent of `spacing`.

Validation should continue to warn or fail when:

```text
stitch_length >= actual_spacing
```

Recommended behavior:

- For `fixed_spacing`, compare against requested spacing.
- For `fit_evenly`, compare against calculated actual spacing.
- For `fixed_count`, compare against calculated actual spacing.

Suggested error:

```text
stitch_length must be smaller than actual stitch spacing
```

Alternatively, allow it but document that stitches may overlap. For leathercraft laser patterns, failing early is better.

## 12. DSL validation rules

### 12.1 Unknown distribution

Input:

```text
holes
  source panel
  distribution magic
end
```

Error:

```text
unknown distribution 'magic'. Use: fixed_spacing, fit_evenly, fixed_count
```

If `fixed_count` is not implemented in the first version, the message should be:

```text
unknown distribution 'magic'. Use: fixed_spacing, fit_evenly
```

---

### 12.2 Missing spacing

If `distribution fixed_spacing` or `distribution fit_evenly` is used, `spacing` is required or should use the existing default.

Current defaults should remain valid.

Recommended default behavior:

```text
holes spacing default = 6
stitches spacing default = 5
```

---

### 12.3 Invalid count

If `distribution fixed_count` is supported:

```text
holes
  source panel
  distribution fixed_count
  count 0
end
```

Error:

```text
count must be greater than 0
```

If `fixed_count` is postponed, then using it should raise:

```text
distribution 'fixed_count' is not supported yet
```

---

### 12.4 Spacing must be positive

Input:

```text
holes
  source panel
  spacing 0
  distribution fit_evenly
end
```

Error:

```text
spacing must be greater than 0
```

---

## 13. Backward compatibility

Existing files should continue to behave exactly as before.

This existing DSL:

```text
holes
  source panel
  spacing 6
  radius 1.2
end
```

should mean:

```text
distribution fixed_spacing
```

The Python API should also preserve old behavior because `distribution` defaults to `"fixed_spacing"`.

## 17. Recommended implementation order

1. Add internal distance distribution helper.
2. Add tests for the helper.
3. Wire helper into existing hole placement logic.
4. Wire helper into existing stitch segment placement logic.
5. Add `distribution` parameter to Python API methods.
6. Preserve default behavior with `distribution="fixed_spacing"`.
7. Add DSL parsing for `distribution`.
8. Add optional DSL parsing for `count` if `fixed_count` is implemented.
9. Add DSL validation tests.
10. Add one or more example `.lcraft` files.
11. Update AI agent reference and user documentation.

## 18. Open design questions

### 18.1 Should `fit_evenly` include corners by default?

Recommended: no.

Keep the existing default:

```text
include_corners=False
```

This avoids changing the visual output too much.

Users can explicitly write:

```python
include_corners=True
```

or in future DSL:

```text
include_corners true
```

if DSL support is added.

---

### 18.2 Should `fit_evenly` distribute per edge or across all selected edges?

Recommended first version: per edge.

Reason: it is easier to reason about and matches existing edge-based behavior.

Future option:

```python
continuous=True
```

or DSL:

```text
continuous true
```

could distribute across the full selected path.

---

### 18.3 Should actual spacing be exposed?

Optional but useful.

Possible return/debug API:

```python
segments = shape.stitch_segments(...)
```

could maybe return metadata later:

```python
StitchDistributionResult(
    points=[...],
    requested_spacing=5,
    actual_spacing=4.9047619,
    count=22,
)
```

Not required for first implementation.

---

## 19. Final recommendation

Implement `distribution="fit_evenly"` as a small, backward-compatible extension to the existing stitch and hole APIs.

The default behavior should stay unchanged:

```python
distribution="fixed_spacing"
```

The new behavior should be opt-in:

```python
distribution="fit_evenly"
```

For the first version, focus on making stitch rows visually balanced while keeping the implementation predictable:

- use target spacing
- calculate interval count from path length
- adjust actual spacing
- respect `include_corners`
- avoid duplicate points on closed contours
- preserve existing files and examples

This feature will make generated leathercraft patterns look more professional, especially on edges whose length is not divisible by the requested stitch spacing.
